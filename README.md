# 销售预测达成看板

单文件、零外部依赖的销售预测达成分析看板（`销售预测达成看板.html`，数据内联，双击即可离线打开）。

- 🌐 **在线看板**：<https://c89135028-ux.github.io/sales-forecast-dashboard/>
- 📦 **仓库**：<https://github.com/c89135028-ux/sales-forecast-dashboard>

> 仓库名使用 `sales-forecast-dashboard`（GitHub 不支持中文仓库名），中文标题见仓库 description。
> 站点入口页为根目录 `index.html`（与 `销售预测达成看板.html` 内容一致）。

**周报与月报在同一份看板里**，靠筛选栏最左侧的「粒度」芯片 `[周] [月]` 切换。

## 看板能力

- **KPI 概览**：订单销量、5 个口径的达成率、加权版 70%-130% 预测量占比，含环比。
- **8 个维度板块**：站点 → 业务组 → BU → 产品组 → 负责人 → 三级分类 → 国家Listing → SKU，每个维度一张宽表，支持逐级下钻。
- **站点趋势图**：两站点并排，柱（分子/分母）+ 折线（达成率）组合图，默认展示最近 4 周 / 6 个月。
- **达成率趋势弹窗**：表格里 5 个达成率数字可点，弹出该项在该口径下的历史趋势。
- **交互**：表头点击排序（默认订单销量降序）、列宽拖动、表头筛选面板、自定义列、左侧目录导航。

## 数据口径

| 指标 | 算式 |
|---|---|
| M版达成 | 订单销量 ÷ 销售预测(最新版) |
| M-1版达成 | 订单销量 ÷ 销售预测(M-1) |
| 加权达成 | 订单销量 ÷ 销售预测(加权) |
| M版断货清洗达成率 | 断货清洗(最新版) ÷ 预测(最新版) |
| 加权断货清洗达成率 | 断货清洗 ÷ 预测(加权) |
| 加权版 70%-130% 预测量占比 | SKU 行粒度上加权达成率落在 [0.7, 1.3] 的预测量 ÷ 该项自身的销售预测(加权) |

缺口 = 预测 − 实际；展示时符号取「实际」视角（实际超出 → `+`，不足 → `-`）。
颜色惯例：红 = 达成 / 超出预测，绿 = 未达成 / 落后。

## 目录结构

```
销售预测达成看板.html     ← 交付物（单文件，数据内联）
build/
  build_all.py            一键跑完全部 4 步
  build_data.py           周报数据（SRCS 多源滚动 → data.json）
  build_data_month.py     月报数据（SRCS 多源滚动 → data_month.json）
  merge_data.py           合并为 data_all.json
  build_html.py           注入模板 → 成品 HTML
  dashboard_template.html 模板（粒度无关）
  verify_data.py          换源硬校验（周+月，源表 ↔ json 对账）
  test_dashboard.js       回归测试（无依赖 DOM 桩）
  verify_backup.py        备份快照双向校验
.workbuddy/memory/        项目约定与决策记录
```

## 数据是滚动的

数据源表列表按顺序读入并拼接，**同一个周期以靠后的表为准**；新数据到手时**追加**到列表末尾即可，历史周期自然累积（不整批替换）。

- 周报：`日明细数据 (21).xlsx`（8/23~9/13 四周）+ `(24).xlsx`（9/20、9/27 两周）→ **6 周**
- 月报：`日明细数据 (20).xlsx`（7、8 月）+ `(25).xlsx`（完整 9 月）→ **3 个月**

> ⚠️ 源表是历史数据的唯一来源（`data.json` 是聚合结果、无法反解回明细），构建脚本会读取它们。
> 换源时把新表路径追加到 `build_data*.py` 顶部的 `SRCS` 列表即可。

## 构建

```bash
python build/build_all.py      # 周报 → 月报 → 合并 → 生成 HTML
python build/verify_data.py    # 硬校验：源表 ↔ json 对账（须 ALL CHECKS PASSED）
node   build/test_dashboard.js # 回归测试（须 RUNTIME OK）
```
