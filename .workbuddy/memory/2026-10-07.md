 教训：**遇到「新表周期 ⊂ 已有周期」时，默认应该是「追加」而不是「替换」**，除非用户明说只保留最新。）

### 正确做法（与月报同一套多源机制）
`build_data.py` 的 `SRC` → **`SRCS` 列表**，按顺序读入并纵向拼接；同一个「周首日」以靠后的源为准
（用于某周被重出时覆盖；本次各源互不重叠，所以就是纯追加）。
- `(21)` 历史 4 周：08-23 / 08-30 / 09-06 / 09-13
- `(24)` 最新 2 周：09-20 / 09-27
- → **6 周**（8/23 ~ 9/27），订单销量合计 **148,524 件**

实现与月报完全一致：`read_source(path)` + `merge_sources(paths)`（先算 `owner` 归属源，再**整周期**取该源数据；
⚠️ 不能写 `drop_duplicates(subset=[时间列])`）。周报的 `TIME_COL = '周首日'`。
两表列集合与列顺序**完全一致**（17 列），可直接拼接；合并后无重复行。
`payload['source']` 变成 `日明细数据 (21).xlsx + 日明细数据 (24).xlsx`。

### 滚动机制的两个操作要点
1. **以后每批新数据到手，把新表 `append` 到 `SRCS` 末尾**（不要替换旧条目），历史就自然累积。
2. ⚠️ **源表文件是历史数据的唯一来源，构建要读它们，不能让用户清理掉**
   （尤其是 `D:/Thinkpad/下载/` 里的 (20)(21)(24)(25)）。若将来源表丢失，`data.json` 是聚合结果、**无法反解回明细**，历史就重建不出来了。

1. **GitHub 不支持中文仓库名**：`create_repository` 传「销售预测达成看板」→ **实际仓库名被规范化成 `-`**，

2. **私有仓库无法启用 Pages（Free 计划）**：实测 `POST /repos/{o}/{r}/pages` 在私有仓库返回
   **422 `Your current plan does not support GitHub Pages for this repository`**（账户 plan = `free`）。
   → 所以先 `PATCH /repos/{o}/{r}` 传 `{"private": false}` **转公开**，再建 Pages。
3. **`workbuddy_sites_deploy` 工具在当前环境不可用**（`Tool "workbuddy_sites_deploy" is not available`），

4. **Pages 入口页必须是 `index.html`**：仓库根目录原来只有中文名 `销售预测达成看板.html`，
   Pages 访问根路径会 404。→ 在**仓库根目录**补一份 `index.html`（内容与中文名文件**完全一致**，md5 相同），
   中文名文件保留供本地双击使用。
5. **Pages 启用命令**（`gh` CLI 不可用，用 curl + git 凭据）：
   ```bash
   TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')
   curl -X POST -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
     https://api.github.com/repos/c89135028-ux/sales-forecast-dashboard/pages \
     -d '{"source":{"branch":"main","path":"/"}}'
   # → HTTP 201，返回 html_url
   ```

### 踩坑记录（工具层）
- ⚠️ **`git push` / `curl -X POST` 在沙箱里会被 SIGTERM 中断**（无输出、exit 1）。重试往往就能过；
  被中断时先用 `git log` / `git ls-remote` 确认是否已成功，不要盲目重跑。
- ⚠️ **push 不要用裸 `git push origin main`**（会去走凭据交互而挂起）：改用
  `git push "https://USER:$TOKEN@github.com/USER/REPO.git" main`。
- ⚠️ **`timeout 15 bash -c '...git credential fill...'` 在子 shell 里会失败**（`token 长度: 0` → HTTP 401），
  必须直接管道：`printf ... | git credential fill`。
