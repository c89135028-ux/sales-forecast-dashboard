# 项目长期约定：销售预测达成看板

## 产物与构建
- **一个交付物：`销售预测达成看板.html`**（单文件、数据内联、零外部依赖，双击可离线打开）。
  **周报 + 月报在同一份看板里，靠筛选栏最左侧的「粒度」芯片 [周] [月] 切换**（用户明确要求，不要再拆成两个文件）。
- 🔴 **看板是「滚动窗口」——新数据只追加，绝不整批替换历史**（用户 2026-10-07 明确纠正：「是滚动你懂吗？把最新数据加上去就行，不是覆盖」）。
  每批新数据到手时，把新表 **append 到 `SRCS` 末尾**即可，历史周期自然累积。
  ⚠️ **判断依据：「新表覆盖的周期」是已有周期的子集/紧邻延伸时，默认按「追加」处理**，除非用户明说只要最新。
  ⚠️ **源表文件是历史数据的唯一来源**（`data.json` 是聚合结果、**无法反解回明细**），构建时要读它们，不能让用户清理掉。
  当前源表：周 = `日明细数据 (21).xlsx` + `(24).xlsx`（D:/Thinkpad/下载/）；月 = `(20).xlsx` + `(25).xlsx`。

- **数据契约**：`data_all.json = {builtAt, modes:[{…, key:'week', name:'周'}, {…, key:'month', name:'月'}]}`，每个 mode 字段与单期数据完全一致（periods/sites/dims/recs/unit/unitName/trendWin/source/filter）。

## 口径（用户明确给定，勿擅改）
- 达成率：M版达成 = 订单销量 ÷ 销售预测(最新版)；M-1版达成 ÷ 销售预测(M-1)；加权达成 ÷ 销售预测(加权)；M版断货清洗达成率 = 断货清洗(最新版) ÷ 预测(最新版)；加权断货清洗达成率 = 断货清洗 ÷ 预测(加权)。
- 缺口 = 预测 − 实际：M版订单预测缺口 = 预测(最新版) − 订单销量；M版断货清洗缺口 = 预测(最新版) − 断货清洗(最新版)；加权断货清洗缺口 = 预测(加权) − 断货清洗。
- 加权版 70%-130%：在 **SKU 行粒度**判定该 SKU 加权达成率是否落在 [0.7,1.3]，命中则计入其销售预测(加权)；**占比的分母是「本项自身」的销售预测(加权)**，随行变化（不是整体）。
- **站点顺序固定为「墨西哥站 (MX) → 巴西站 (BR)」**：`build_data.py` 里 sites 的排序键写死 mx 优先；站点卡片/筛选 chips/趋势面板/站点明细表全部跟随 `D.sites` 顺序（明细表**不要**再按名称排序，否则会与上方卡片顺序不一致）。加新站点时改这个排序键。
- 维度：站点 / 业务组 / BU / 产品组 / 负责人 / 三级分类 / 国家Listing / SKU（国家Listing、SKU 为高基数明细维度；SKU = 「最早SKU|预测SKU」组合，显示时拆两列）。
- **listing 回填规则**：按 **(国家, 最早SKU) 双键**（同一 SKU 在巴西/墨西哥的 listing 编码不同）查对应表；**只补空值，源表已有值一律不动**——即使源值（同族合并编码）与对应表（单 SKU 编码）不同也以源表为准；对应表给「淘汰」等状态词时原样显示、不并入「（未标注）」；补不上的才归「（未标注）」。
  当前周表 (21)+(24)：空 1,225 行 → 补 1,223、余 **2 行「（未标注）」**；
  当前月表 (20)+(25)：空 614 行 → 补 611、余 **3 行「（未标注）」**（对应表确实缺这几个 SKU）。
  「（未标注）」只出现在 国家Listing 这一个维度。
  ⚠️ **周期数可少至 2**（(24) 只有 9/20、9/27 两周）：模板 `trendPeriods()` 的 `end-start<1` 分支会自动兜底画 2 个点，文案变「· 近 2 周」，**不需要改模板**。

## 视觉与交互约定
- **红绿语义全页唯一**：红 = 达成 / 超出预测；绿 = 未达成 / 落后（缺口为正时用绿）。新指标上色前先对照这条。
- 达成率色阶五档：≥110% 实心深红+白字、100~110% 浅底红、90~100% 浅底橙、80~90% 浅底绿、<80% 实心绿+白字；图例在**每个板块底部各一份**。
- 缺口展示采用 `fmtGap(v)`：**实际超出预测 → `+`，实际少于预测（不足）→ `-`**（符号与算式值相反）；颜色仍按算式（正=绿/未达成、负=红/超出）。右下角说明「绿色＝实际少于预测（-）　红色＝实际超出预测（+）」。环比等变化量保留原有 `+`/`-`。
- 表格：`table-layout:fixed` + `<colgroup>` 固定列宽，表头与数值全部居中（名称列左对齐、序号居中）。
- 🔴 **表头文字是用户给定的原文，一个字都不许改**（不要重排成"达成率·M版"这种、不要加 `<br>`、不要缩写）。表头放不下时**只能加宽对应列**，不能动文字。
  列宽按实测来：可用宽 = 列宽 − 左右 padding(20) − 排序箭头(14)。当前实测占宽：mRate 78 / m1Rate 89 / wRate 78 / mOosRate 129 / wOosRate 129 / f4 129 / f3 120 / f1 119 / a 78 / f5 175 / mGap 119 / mOosGap 119 / wOosGap 119 / f1q 165 / bandShare 88。
  `COLW = [38,150, 132×5, 140×4,178, 122×3, 168,132]`（表宽 2252px）；**改表头文字后必须重新量一遍并同步 COLW**。
- **表头点击排序**：15 个指标列表头都可点，**一下降序、再点一下升序，默认订单销量降序**。状态 `state.sort[表key]={k:'列键',dir:-1|1}`（表 key = `wideTable` 的 tblKey，含站点表的 `'_site'`），每张表独立记忆。
  排序取值挂在 `COL_DEF` 的 `v:o=>…` 上；指示器 `<i class="sk">` 固定 11px 宽（▼/▲/⇅ 切换时表头文字不跳）。**点击必须排除 `.rz`（列宽手柄）与 `.fbtn`（筛选按钮）**，否则拖列宽会顺带排序。切换粒度时排序重置为默认。
- **国家Listing 表**在名称列前多一列「三级分类」（取该 listing 在当前筛选内订单销量最大的分类，多分类时标 `+N`）；三列固定：`#`/三级分类/国家Listing。
- 附属列（名称列前的身份列）由 `AUX_DEFS` 声明：国家Listing 表 = 三级分类；**SKU 表 = 三级分类 + 国家Listing**（`#`/三级分类/国家Listing/最早SKU/预测SKU 五列固定）。
- 每列附属列**都带自己的表头筛选**（筛选键 `维度@列名`，状态存 `state.hideAux`），只影响本表、不联动其他板块；多列筛选取交集。附属列与名称列同字体（600 / 12.5px / `--ink`）。
- 所有宽表**列宽可拖动调整**（拖表头右边界 9px 手柄，双击该手柄恢复默认），宽度存 `state.colW[维度]`，重渲染后保留；固定列偏移由 `--lka/--lk1/--lk2` 变量推导。
- 交互克制：**不挂排序下拉框、不挂板块内关键词搜索框、不挂表底说明小字**；检索统一走「表头筛选面板」（内含搜索 + 勾选 + 全选/清空/重置/应用）。
  排序的入口是**点表头**（用户后来明确要求），所以不要在别处再加排序控件。
- 高基数维度（项数 > 20）**不展示「订单销量占比」构成条**（`compBar` 的 `COMP_MAX=20` 门槛）：三级分类/国家Listing/SKU 一律不画，小维度保留。
- 每张宽表右上方一个「自定义列」按钮（勾选显示哪些指标列，全局生效，面板底部：全选/清空/默认/完成），入口挂在该表格的小节标题行右侧。
- 趋势图：默认近 `trendWin` 个周期（周报 4、月报 6；数据不足时按现有周期数），折线指标可切换（5 项），**柱状必须随指标联动**（折线 = 柱1 ÷ 柱2）。
  **两根柱都要标数值**（柱1 用 `#2f5bd7`、柱2 用 `#8593aa`）；窄面板下两标签横向放不下，要**强制上下错开 ≥14px（一个行高）**；标签顶部夹取位置是 **`PT-6`**（不是 `PT+9`，否则高值标签会顶格重合成一坨）。自查：遍历 `.bar-lbl` 判「`|Δy|<12` 且横向相交」，站点并排/单站点/弹窗三种视图都要 0 重叠。
- **各维度板块的达成率数字可点 → 弹窗看该项自己的趋势**（`#tpop`，与站点趋势图同一套「柱 + 折线」画法）：
  表格 5 个达成率列渲染成 `<td class="rc rt" data-rt="口径键">`（`rowHTML` 的 `clkRate` 参数，`wideTable` 里 `clkRate = tblKey && tblKey!=='_site'` —— **站点明细表不参与**）。
  口径定义在 `RATE_TREND`（key 与 `COL_DEF` 的达成率列一一对应，柱1=分子、柱2=分母、折线=柱1÷柱2，必须自洽）。
  **弹窗内不提供口径切换**（用户明确要求「点M版达成显示M版达成、点M-1显示M-1版」）：头部只放一个只读口径标签 `.tp-metric`，不要下拉。
  关闭三通道：✕ / 点遮罩 / Esc；`renderAll()` 末尾刷新弹窗，所以开着时改站点/下钻/粒度都会跟着更新；点达成率要 `stopPropagation()` 避免误触发整行下钻。
  **不要再给维度板块加常驻的趋势图**（做过一版多折线，被用户否掉改成这个弹窗）。
- 趋势图**宽度按面板实宽自适应**：单站点时面板占满整行（`.trend-grid.one{grid-template-columns:1fr}`），SVG 内部宽度 = 面板宽−26，满宽时柱体加粗到 44px、画布高 300；窗口缩放变化 >60px 时自动重绘。
- 左侧目录导航：8 个维度 + 站点；scroll spy 高亮；跳转 = 平滑滚动 + 原生锚点兜底。
  尺寸（用户嫌小后调大一档，别再改小）：列宽 **206px**、项字号 **14px**、序号 12px、标题行 12px、项内边距 `10px 12px`、卡片内边距 `15px 12px 12px`；选中态左侧指示条 4px、`left:-12px`（= 卡片 padding-left，改内边距必须同步改它）。窄屏 <1180px 隐藏目录。
- **站点 KPI 行固定 7 列、恒定一行**（`.kpis{grid-template-columns:repeat(7,minmax(0,1fr))}`，KPI 数量固定 7 张，不要用 auto-fit 否则会 6+1 换行）；`@media (max-width:1000px)` 才退回 `auto-fit` 自适应换行。
- **选中单个站点时隐藏「各站点表现」小节标题 + 站点卡片**（内容与上方 KPI 行重复）；「全部站点」时显示。站点明细表（15 列完整指标）保留。
- **站点明细表不打「已下钻」标记**：站点是在顶部 chips 选的，`wideTable` 的 `onName` 固定传 `null`（只呈现该站点数据）。该标记只留给维度板块（点行下钻时用）。
